Sesión

Con objetivo y control

  • Inicia con un objetivo o síntoma; se puede pausar, reanudar o cancelar.
  • Se recupera por lease si un worker cae.
Presupuesto

Tope renovable

  • Al agotarse, la sesión se pausa.
  • El channel manager autoriza ampliaciones una a una, auditadas.
Alcance

Cambios aislados

  • Pruebas, copias experimentales de configuración, modelos XGBoost y generaciones de Vector Store.
  • No toca entidades activas.

Optimizador · evaluación

Especialistas y verificadores

Especialistas

Un contrato común

  • Reciben alcance, hipótesis y presupuesto; devuelven resultado, métricas, evidencia y verificación.
  • Se registran por área sin cambiar el orquestador.
  • Un generador propone modus operandi nuevos a partir de patrones.
Verificadores

Qué comprueban

  • Evaluador global: función objetivo sobre desenlaces maduros.
  • Integridad de ruta: saltos, bucles, fallos y escalamientos.
  • Comparación: no declara ganador sin muestra mínima.
Diagnóstico

Dónde y por qué falla

  • Por segmento, canal, etapa y ruta.
  • Mínimo de 30 casos por corte; nunca filas, ids ni payloads.
Evaluación pareada

Misma muestra, versiones fijas

  • Línea base y candidato sobre la misma muestra, con modelo, configuración, biblioteca y Vector Store fijados por hash.
  • Corre el flujo real, con efectos operativos simulados.

Monitoreo · salud técnica

Telemetría y rastro de auditoría

Telemetría

OTLP como único contrato

  • La app solo conoce OTEL_ENDPOINT; el Collector es la frontera.
  • Trazas de llamadas LLM, dependencias y casos de uso clave.
  • Tempo, Loki, Prometheus y Grafana detrás del Collector.
  • Nunca customer_id ni monto exacto en atributos.
Auditoría

Todo deja rastro

  • Cada petición HTTP y mutación persistida pasa por el puerto de auditoría.
  • El acceso al payload crudo tiene su propio registro.
  • Confirmaciones, aprobaciones, activaciones y correcciones con autor y hora.
Calidad

Juez del razonamiento

  • Un juez LLM evalúa cada decisión como dato técnico adicional.
  • El contenido de prompts solo se captura si se activa.
Audiencias

Dos fuentes independientes

  • Negocio lee la API de métricas de ARIA.
  • Plataforma lee Grafana.

Acceso y resguardo

Autenticación, separación de funciones y continuidad

Autenticación

Acceso con rol

  • Login con JWT; /auth/me entrega rol y permisos.
  • Contraseñas PBKDF2-SHA256.
  • Alta de usuarios con token de arranque que no se guarda.
Separación

Nadie decide solo

  • Quien solicita un despliegue no lo aprueba.
  • Quien opera no amplía presupuesto.
  • El agente nunca promueve a producción.
Continuidad

Backups y retención

  • Respaldo y restauración de DynamoDB, OpenSearch y objetos.
  • Retención configurable del payload crudo y del chat.
Quién hace qué

Seis roles, seis responsabilidades

Fraud analyst

Marca. Toma las alertas escaladas, revisa la evidencia del agente y resuelve con su decisión.

Ops analyst

Observa. Vigila embudo, SLA, errores y capacidad en dashboard y monitor.

Channel manager

Dirige. Conduce al agente optimizador: objetivo, segmentos, enrutamiento y presupuesto.

Manager

Gobierna. Cambia la configuración general, el esquema de alertas y los estados on/off.

Release manager

Aprueba. Revisa la evidencia, autoriza el lanzamiento y avanza shadow → canary → full.

Data analyst

Prepara. Cura la biblioteca, los datasets y entrena los modelos que ARIA consulta.

Plan de adopción

Compuertas de paso entre fases

Cada fase tiene un dueño, un criterio medible y una forma de volver atrás.

Fase 1 · Aprender

Calidad estable

Sale cuando la calidad medida sobre las alertas descargadas supera el umbral acordado y se sostiene prueba a prueba.

QUIÉN: Analistas (descargan), Channel manager, Data analyst, equipo de fraude

Fase 2 · Integrar

Todo concilia

Sale cuando un analista corre el script por su cuenta y lo enviado, recibido y procesado coincide, sin pérdidas ni duplicados.

QUIÉN: Analistas, Plataforma, Release manager

Fase 3 · Resistir

Salida para cada falla

Sale cuando aguanta la carga esperada y cada falla ensayada tiene una salida probada.

QUIÉN: Release manager, Ops analyst

Fase 4 · Escalar

Un escalón a la vez

Cada porcentaje se cumple antes del siguiente, con retroceso inmediato por el interruptor.

QUIÉN: Manager, Release manager
